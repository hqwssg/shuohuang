# 碳排放核算全流程设计说明

## 一、流程总览（5 步）

```
┌───────────────────────────────────────────────────────────────────────────────┐
│                        碳排放核算 5 步流程                                    │
│                                                                               │
│  Step 1   创建核算任务记录（CalculationTemplate）                             │
│  Step 2   遍历模版节点 → 创建核算节点快照（CalculationNode）                  │
│  Step 3   采集节点(typeId=3) → 能耗计量值计算 → 碳排放量计算 →                 │
│          写入 sys_emission_collection_node_data                                   │
│  Step 4   核算/根/运输节点 → 自底向上逐级汇总（CalcNodeSummaryProcessor）      │
│          写入 sys_emission_calc_node_summary                                      │
│  Step 5   更新核算任务状态 → SUCCESS / FAILED                                 │
└───────────────────────────────────────────────────────────────────────────────┘
```

## 二、触发方式

**定时触发**（唯一入口，Job Profile 下激活）：`EmissionScheduler.java`

| 条件   | 说明                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------- |
| 调度频率 | 每分钟一次（`@Scheduled(cron = "0 * * * * ?")`）                                                                  |
| 扫描对象 | 仅 `templateType=2`（核算模版）且 `enabled=true` 的模版                                                               |
| 判断依据 | 模版的 `task_config` JSON（cycleType + executionTime + startDate + endDate + delayDays + monthDays/weekdays 等） |
| 执行周期 | DAILY / WEEKLY / MONTHLY / QUARTERLY / YEARLY                                                              |
| 延迟核算 | `delayDays` 天（默认 0，前端编辑时缺省 3），实际触发日期 = 统计周期结束后宽限期                                                          |
| 执行方式 | 满足条件则提交到 `AsyncTaskService` 异步线程池执行                                                                        |

## 三、前置条件与数据准备

在核算执行前，需要以下数据已准备好：

| 数据        | 来源表                                  | 关键字段                                                                 |
| --------- | ------------------------------------ | -------------------------------------------------------------------- |
| 核算模版      | `sys_emission_template`                  | template_type=2, enabled=true, task_config（JSON）                     |
| 节点树       | `sys_emission_node`                      | 按 template_id 分组；typeId=1 根 / 2 核算 / 3 采集 / 4 运输                     |
| 节点配置      | `sys_emission_node_config`               | collection_point_type + collection_point_id + carbon_emission_factor |
| 采集点（电力）   | `sys_emission_meter_info`                | emission_subcategory, is_cumulative, measurement_unit...             |
| 采集点（化石燃料） | `sys_emission_fossil_fuel_meter_info`    | fuel_type, is_cumulative, measurement_unit...                        |
| 采集点（外购热能） | `sys_emission_purchased_heat_meter_info` | heat_type, is_cumulative, measurement_unit...                        |
| 采集记录      | `sys_emission_collection_record`         | collection_status=1（成功），含 reading_value + collection_time            |
| 因子模版      | `sys_emission_factor_template`           | 核算模版通过 `sys_emission_template.factor_template_id` 关联                     |
| 缺省因子      | `sys_emission_default_factor`            | (template_id, subcategory_name) 匹配，status=1 启用                       |

## 四、Step 1：解析核算周期 + 创建任务记录

**文件**：`EmissionCalculationServiceImpl.java` — `executeEmissionCalculation()`

```
输入：templateId
动作：
  1) 查 sys_emission_template 获取模版
  2) 解析 task_config JSON → cycleType + delayDays → [cycleStartDate, cycleEndDate]
     - DAILY：adjustedDate - 1 天
     - WEEKLY：上一周（周一~周日）
     - MONTHLY：上个月（1日~月末）
     - QUARTERLY：上一季度
     - YEARLY：上一年（1/1 ~ 12/31）
     - 默认：上月1日~上月末日
  3) 写 sys_emission_calculation_template（status=RUNNING）
```

## 五、Step 2：遍历节点 + 创建核算快照

**文件**：`EmissionCalculationServiceImpl.java` — `executeEmissionCalculation()` 内循环

```
输入：templateId, calcTemplateId
动作：
  1) 查 sys_emission_node（WHERE template_id = ?）
  2) 遍历每个节点：
     - 写 sys_emission_calculation_node（快照，保存 typeId + parentId + nodeCategory）
     - typeId=2 时查 sys_emission_node_info 取 nodeCategory 填入
     - typeId=3 → 进入 Step 3（采集节点核算）
     - typeId=1/2/4 → 不处理（待 Step 4 汇总）
```

## 六、Step 3：采集节点核算（核心计算）

**文件**：`EmissionCalculationServiceImpl.java` — `processCollectionNode()`

### Step 3.1 — 能耗计量值计算（EnergyMeasurementCalculator）

根据 `isCumulative` 分两种算法：

```
算法A（累加量 isCumulative=1）:
  - 查 collection_record（collectionStatus=1 成功）
  - 起始记录：距 cycleStartDate 最近（优先起始日之后）
  - 截止记录：距 cycleEndDate 最近（优先截止日之前，凌晨6点前采集算前一天）
  - energyValue = 截止读数 - 起始读数（<0 时置 0）
  - 修正值：起始/截止超范围按日均扣减，缺失按日均补加

算法B（非累加量 isCumulative=0）:
  - 查 collection_record（collectionStatus=1），过滤 billingCycle 空
  - 筛选 billingCycleStart ≥ cycleStart AND billingCycleEnd ≤ cycleEnd 的记录
  - energyValue = 有效记录 readingValue 之和
  - 修正值：超范围扣减、空缺补加、重叠扣减
```

**数据状态判定**：

| 值   | 含义      | 说明             |
| --- | ------- | -------------- |
| 1   | 完整      | 起止日期匹配、无空缺、无重叠 |
| 2   | 没有数据    | 无任何成功采集记录      |
| 3   | 数据不完整   | 起止不匹配或中间有空缺    |
| 4   | 数据超范围   | 记录整体在核算周期之外    |
| 5   | 不完整且超范围 | 组合情况           |

**例外判定**（采集点启停时间豁免）：

- 起始缺失但采集点在 cycleStartDate 之后**才创建/启用** → 不视为不完整
- 截止缺失但采集点在 cycleEndDate 之前就**已停用** → 不视为不完整
- 非累加量中间空缺段若完全落在"停用后再启用"的区间内 → 不补加

### Step 3.2 — 碳排放因子确定（回退机制）

```
优先级：
  ① 采集节点配置因子（sys_emission_node_config.carbon_emission_factor）
  ② 模版缺省因子（sys_emission_default_factor WHERE template_id=? AND subcategory_name=? AND status=1）
  ③ 均为空 → 跳过碳排放计算（carbonEmission = null）
```

### Step 3.3 — 碳排放量计算

```
carbonEmission          = energyMeasurementValue      × factor    （保留6位小数）
adjustedCarbonEmission  = adjustedEnergyValue         × factor    （保留6位小数）
```

### Step 3.4 — 写入核算结果

写入 `sys_emission_collection_node_data`（CalculationNodeData 实体），字段包括：

- 采集点元数据：collectionPointType/Id、emissionCategory、emissionSubcategory、isCumulative、isMobileSource、measurementUnit
- 能耗场景：energyCategoryL1/L2/L3、energyUseCategory
- 计算结果：energyMeasurementValue、adjustedEnergyValue、carbonEmission、adjustedCarbonEmission、carbonEmissionFactor
- 状态：dataStatus（1-5）、dataMissingDescription、collectionRecordStartDate/EndDate

## 七、Step 4：逐级汇总（自底向上）

**文件**：`CalcNodeSummaryProcessor.java`（仅 `@Profile("job")`）

**汇总对象**：typeId = 1（根节点）、2（核算节点）、4（运输节点），统一算法。typeId=3（采集节点）不参与此步。

**处理流程**：

```
1) 幂等：先删 calcTemplateId 下所有历史汇总
2) 拉取全部 CalculationNode 快照
3) 构建辅助 Map：
   - byId           — nodeId → CalculationNode
   - childrenByParent — parentId → [直属子节点]
   - levelMap       — 层级（递归计算，根=1，逐级+1）
   - leafMap        — 是否"叶子核算节点"（直属子节点全为 type!=1/2/4）
4) 排序：按 level 倒序（最深层先处理，保证子节点先汇总，父节点后汇总）

每个目标节点：
  Step A — Direct（直属采集节点汇总）：
    - 过滤 typeId=3 的直属子节点 → 查 sys_emission_collection_node_data
    - 分组 key = (energyCategoryL1, energyCategoryL2, energyCategoryL3, emissionSubcategory)
    - 组内 energy/carbon 累加；factor 按 energy 加权平均
    - 单位换算：lookupCalcUnit(subcategoryCode) → UnitConversionService 换算到核算单位

  Step B — Children subtotal（子节点汇总合并）：
    - 过滤 typeId∈{1,2,4} 的直属子节点 → 查 sys_emission_calc_node_summary
    - 相同分组 key 的 subtotal_energy/carbon 累加

  Step C — 合并 + 写 sys_emission_calc_node_summary：
    - subtotalEnergy = directEnergy + children.subtotalEnergy
    - subtotalCarbon = directCarbon + children.subtotalCarbon
    - summary_source 位掩码：1=direct 2=children（合并用 OR）
```

**UnitConversionService**：`convertToCalculationUnit(subcategoryCode, fromUnit, value)` — 将不同采集点的计量单位统一换算到该小类在 `sys_emission_calc_unit_default` 表中定义的核算单位（如 Nm³、万Nm³），保证同一小类下不同采集点数据可直接累加。

## 八、Step 5：更新任务状态

```
成功 → sys_emission_calculation_template.status = 2
失败 → status = 3 + errorCode + error 日志（整体异常才置 FAILED，单节点失败不中断）
```

## 十、核心公式汇总

| 环节          | 公式                                                                                                   |
| ----------- | ---------------------------------------------------------------------------------------------------- |
| 累加量能耗       | `energyValue = 截止读数 - 起始读数`                                                                          |
| 非累加量能耗      | `energyValue = Σ 有效记录 readingValue`                                                                  |
| 碳排放量        | `carbonEmission = energyMeasurementValue × emissionFactor`                                           |
| 修正碳排放量      | `adjustedCarbonEmission = adjustedEnergyValue × emissionFactor`                                      |
| 日均能耗        | `累加量：(末读数-首读数)/首末天数`；`非累加量：Σvalue/Σ天数`                                                               |
| 加权平均因子      | `Σ(factor_i × energy_i) / Σ(energy_i)`                                                               |
| 汇总 subtotal | `subtotal = direct + Σ child.subtotal`                                                               |
| 单位换算        | `convertedValue = originalValue × UnitConversionService.convert(subcategory, fromUnit, calcUnit, 1)` |

## 十一、容错与边界处理

| 场景                              | 处理方式                                                                |
| ------------------------------- | ------------------------------------------------------------------- |
| 采集节点异常（无配置/无采集点）                | 写 `sys_emission_collection_node_data` 占位（dataStatus=2，energy=0），整体核算不中断 |
| 采集点能耗为 0                        | carbonEmission 置 0                                                  |
| 碳排放因子为 null                     | 查模版缺省因子（sys_emission_default_factor），仍无则跳过碳排放计算                         |
| 模版缺省因子存在但 status≠1 或 value=null | 视为无缺省因子，不采用                                                         |
| Step 4 汇总失败                     | 抛 RuntimeException，整体 status=FAILED + errorCode=2                   |
| 单位换算异常                          | 捕获并保持原值，不中断汇总                                                       |
| 同一采集周期多次核算                      | Step 4 幂等：先删 calcTemplateId 下历史汇总再重算                                |
